# Replication packages

The audit in `docs/underlay_drift.md` showed that the city rewrites its tables in place. A citation of the form "dataset 43nn-pn8j, rows updated at T" cannot be rerun after T, because the table as it was at T is no longer published. The project's Socrata cache keeps a copy of every response, but `data/cache/` is git-ignored, so a reader of the repository does not have it. A replication package closes that gap for one claim. It copies the inputs the deciding number is computed from, pins each by sha256, and reruns the number outside the repository.

## Design

`tools/replicate.py <claim-id>` writes `replication/<claim-id>/`. The folder holds the following files.

- `manifest.json` has five sections. The `claim` section holds the registration and its sha256, the commit that added it, the `prereg/<id>` branch on the remote and its SHA (from `git ls-remote origin`), the outcome, its revision history (the `history` field and every commit of the outcome file) and the referee reports with their sha256. The `code` section lists the scripts the claim used, found from the rerun recipe, from paths named in the registration or outcome, and from a search of `analyses/` for the claim id as a whole word. Each script has its git blob hash, its first and last commit, and whether the working copy equals HEAD. The section also gives the repository commit and the seeds, draw counts and commits quoted in the registration. The `data` section has one entry per source in the outcome, described below. The `environment` section gives the Python version, the `uv pip freeze` of `~/.venvs/nyc-concordance`, the platform and the OS. The `inputs` and `deciding` sections list every input file and the deciding number with its tolerance.
- `inputs/` holds copies of the inputs, which keep their repository paths, up to a total of 15 MB (`--cap-mb`; the first two packages were built with 20 MB). The pages of one Socrata query are copied all together or not at all. Files beyond the cap are listed in the manifest by path, size and sha256. For recipes added after the first two, the tool runs the wrapper once in the repository under a Python audit hook and copies only the files the rerun opens; every other source is pointed to by hash. A recipe may also name a slice of a large CSV file, such as the columns of the Central Park station file that `concord/noaa.py` reads. The manifest then gives the sha256 of the slice and of the whole file, and the rule that makes one from the other.
- `code/` holds copies of the modules the rerun imports, and `code/rerun.py`, a wrapper that points the code at `inputs/` and blocks `requests.get`, so that a missing input fails loudly instead of being fetched again.
- `verify.py` and `run.sh` check every input hash, rerun the deciding number and compare it with the outcome. The result is MATCH, DRIFT (an input differs from its pin) or MISMATCH (the inputs are intact but the number differs, so the code or the environment has changed). `--refetch` re-runs each copied Socrata query and the NOAA download, compares the rows with their pinned hash (`rows_sha256`, the hash of the rows alone, since the cached file also holds a fetch time), checks `rowsUpdatedAt` for sources that were not copied, and, where the recipe allows, reruns the number on the live data.
- `requirements.txt` pins the packages the rerun imports, and its first line names the Python version the package was recorded under. `README.md` names that version and the `uv venv --python` command that installs it, and says what is pinned, what is only pointed to and what a reader needs.
- The manifest's `not_rebuilt` section lists each intermediate table that the rerun reads but cannot rebuild from what the package carries. Each entry names the table, the script that built it, why it cannot be rebuilt here, and each input it was built from, with its sha256 and the place in the manifest where it is pointed to. The README repeats this under "Tables this package cannot rebuild". Where a claim has a registered placebo or one named by the referee, the recipe reruns it and the manifest records it under `deciding.placebo`; `verify.py` compares it like the deciding number.
- `underlay/` is written with `--underlay`. It holds `schemas.json`, `records.jsonl` (types ReplicationPackage, PackageInput, PackageCode and PackageSource, one record per line) and `manifest.json` with each record's hash, computed with `tools/underlay_export.record_hash`. Nothing is pushed.

The data entries depend on the source type. A Socrata source gets its dataset id, `rowsUpdatedAt`, exact SoQL, fetch time and the sha256 of each cached page, found by recomputing the cache key of `concord/socrata.py` with and without `$offset`. A System graph source gets the release name ("July 1, 2026 release", from the challenge; the API returns no version id), the dataset version, each cached request path that names a relationship or concept in the registration's graph evidence, and the sha256 of its response. The key is never read; the cache stores responses without it. A NOAA source gets the file URL, its Last-Modified header and its sha256. A TLC file gets its URL, path under `~/opt/nyc-concordance` and sha256, an Underlay source gets its collection, version hash and ARK, and other sources are recorded as given.

A deciding number can be rerun only when the claim has a recipe in `RECIPES`. The recipe names the code to copy, the derived tables to copy, the upstream files to point to, the wrapper and the tolerance. Without a recipe, `verify.py` checks hashes only and reports NO_RERUN.

Neither claim's script was written to be rerun alone, so each recipe uses the smallest wrapper that reruns the deciding number. For heat-shootings, `analyses/heat/shootings.py` fits eight sensitivity models and writes into `data/derived/heat/`. The wrapper calls its `build()` and `nb_fit()` unchanged for the primary model only. For levers-vacant-lot-trial-match, `analyses/levers/lot_test.py` reads and writes `data/derived/levers/`. The wrapper copies its three input tables into `work/levers/` and sets `lot_test.D` there.

## The fresh replication

Both package folders were copied to a scratch directory outside the repository and given to a new agent, which was told not to read the repository, `~/opt`, `~/.venvs` or `~/.config`. The agent built its own environment with `uv venv --python 3.12` and installed both `requirements.txt` files at the pinned versions without substitutions. Both packages printed MATCH with values identical to the recorded ones. The agent then ran both under `sandbox-exec` with reads of `~/Dropbox`, `~/opt`, `~/.config`, `~/.venvs` and `/Volumes` denied and the network blocked, and both still printed MATCH. Its `--refetch` of heat-shootings gave DRIFT for the NOAA file with the deciding number unchanged.

The agent reported the following gaps.

1. The README told the reader to use `python3 -m venv`, and the agent used uv instead; on that machine the `python3` on PATH is Anaconda. This worked, but the README does not name a Python version to install.
2. `--refetch` reports DRIFT whenever a day has passed, because NCEI rewrites the station file daily. The status did not separate that from a change that matters. `verify.py` now writes `live_number_within_tolerance`, and the README explains that DRIFT with that flag true means the sources changed and the number did not.
3. The levers README repeated text that did not apply to it, about NOAA downloads and a System API key. The README is now built from the package's own sources.
4. The levers registration's statement says "about three in ten" lots and "on the order of 20 shootings a year", while the rerun prints 0.417 and 388 shootings a year within 300 m. The README now says that the verdict turns on the registered ranges, and that 388 is the count near the lots, from which the outcome derives 26.4 prevented a year.
5. The runs write `work/`, `code/data/` and `verify_result.json` into the package. These are now named in the README and in the package's `.gitignore`.
6. The levers rerun starts from derived tables. The trial-like classification cannot be rebuilt from the package, because it needs 67 MB of DOB permit pages, NAIP imagery from the Planetary Computer and the MapPLUTO polygons. These are pointed to with their hashes, but they are not copied.

Items 2 to 5 were fixed in the tool before the packages were committed. Items 1 and 6 were fixed on the evening of 13 November: the README now names Python 3.12.10 and the uv command that installs it, and the manifest and README list the tables a package cannot rebuild (`not_rebuilt`). Both packages were rebuilt with these changes; their inputs are unchanged.

The sealed rerun of further-tidal-flooding-trend differs from the in-repository rerun in the thirteenth significant digit (2.000694591935431 against 2.000694591935365), which is floating-point noise well inside the tolerance; all other sealed reruns are bit-identical.

Every rerun reproduced its recorded values to the precision the outcome records them; the tolerances are 0.0001 on ratios unless the outcome records fewer digits (0.005 percentage points for mob-crz-traffic). The placebos are rerun and compared in the same way. The mob-crz-traffic placebos are the registered 2024 pre-trend checks for speed and trips. For street-busway14-m14-speed the standard error of the deciding number is the standard deviation of the 119 placebo DiDs, so the placebo stage is rerun as part of it, and the referee's count of 2 placebos at least as large is reproduced. For bridge-heat-shootings-ems the placebo is the STAB contrast that the registration names as a check outside the causal chain, and the composed prediction is recomputed with its seed (20261112) and 200,000 draws. For further-tidal-flooding-trend the placebo ZIP set and the 7-day and 100-day shifted tides are rerun with the registered seed and 1,000 bootstrap replicates; the rerun takes about four minutes.

Three packages start from intermediate tables they cannot rebuild, and the manifest's `not_rebuilt` section lists each with its inputs and their hashes. For ems-traffic-share-2019-2026 the EMS hourly tables come from SoQL aggregations that are not in the cache, and the taxi tables come from TLC trip files kept in `~/opt`. The wrapper reads only the taxi files that hold rows in January to September of 2019 and 2026, three of them sliced to those months, which keeps the package at 14.4 MB. For food-supermarket-diabetes-zcta the Census columns of `food_zcta.csv` come from nine national Census and ACS files in `~/opt/nyc-concordance/census` (about 400 MB), now pointed to by sha256. For further-tidal-flooding-trend the complaint columns come from `daily_panel.csv`, built from `complaints_by_day_zip.json` (27.8 MB, pointed to by hash). heat-ed-syndromic and bridge-heat-shootings-ems carry a slice of the Central Park station file (the six columns `concord/noaa.py` reads, all rows) instead of the whole 17 MB file.

Three packages carry a cut of files too large to copy, made at build time by a prepare step whose code is in the package as `code/prepare.py`; the manifest lists each source file with its sha256 under `inputs.files[].prepared_from`, so a reader with those files can remake the cut and compare its hash. For rlc-expansion-rearend the cut holds the crashes within 50.5 m of a camera or control intersection (2.6 MB, from the seven h9gi-nx95 pages and the bm4k-52h4 page, 122.9 MB); `rlc_did.build()` counts no others, so the rerun now builds the matched sets itself and also reruns the registered placebo year (1.2496, 1.0519 to 1.488), which was not possible from the saved sets. For turn-calming-ped the cut holds the crashes with a pedestrian injured or killed within 40.5 m of a calming site (1.7 MB, from `crashes.csv` and `left_vehicles.csv` in `~/opt`, 192 MB); the pedestrian count within 40 m is a sum over these crashes only. The referee's placebo, with installation moved 12 months early (0.9119, 0.8252 to 1.0078), is rerun and recorded under `deciding.placebo` with `registered: false`. The left-turn and ring outcomes are not reproduced from this cut. For restaurants-nta-harshness the cut is the Underlay snapshot nyc/restaurant-inspections v1.0.0 with only the fields `evenness_test.load_snapshot()` reads, gzipped (1.2 MB from about 50 MB); the rerun repeats the 10,000-draw permutation with seed 20261113.

Two faults in the tool were found and fixed while building these packages. A source naming several datasets (the parking-violation queries of rlc-expansion-rearend) stopped the build, and Socrata sources hosted on data.ny.gov and health.data.ny.gov were given the city's domain, so `--refetch` would have queried the wrong host. The domain now comes from the source's own URL.

## Limits

A package pins the inputs and the code; it does not pin the operating system or the numerical libraries below Python. Both reruns gave bit-identical numbers on macOS 27 (arm64) under the pinned versions. The tolerance of 0.0001 on the heat-shootings IRR allows for small differences on other platforms. The search of `analyses/` for the claim id finds scripts that mention the claim, such as later bridges and critiques, as well as scripts that compute it. The manifest records how each script was found, and only the recipe's scripts are copied and run.
